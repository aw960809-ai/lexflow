# LexFlow V0.3 — 官方 PDF、答案更正與候審發布防線

**此修改是 Draft PR #1 的品質保護；不得合併 `main` 或聲稱已建成正式題庫。**

## 為何增加這一層

1. 官方考試頁面有 `t=Q`（試題）、`t=S`（公布的測驗標準答案）、`t=M`（更正答案）與 `t=A`（全考試科目答案更正清冊）。`S` 是「公布標準答案」，不代表已完成與最新更正狀態的逐題比對。
2. 114 年司法四等法院書記官「民法概要」原卷同時有 **申論 2 題與單選 25 題**，不可因試卷標題就當作純選擇題。
3. 真實 HTML 候審索引曾有過 80 筆連結；其中「司法五等考試_庭務員類科」被連結到 **32 筆**候審試卷，顯示網頁文字的類科上下文可能繼承錯誤。這是**需核查的警報**，不能假裝每筆題目類科都核對無誤。
4. 考選部的法學知識與英文更正答案，含「多組選項均得分」例外。**不可以只用單一 A/B/C/D 代表所有題目的最終官方給分條件**。

## 工程實作

- `scripts/moex_document_qa.py` 會**重新讀取一份經 allowlist 限制的官方 HTML**，抽取候審索引，從三個具有明確題號／科目的樣本核對 **7 份 PDF**：
  - `201/0405` 的民法概要 `Q`、`S`。
  - `201/0504` 的刑法概要 `Q`。
  - `201/0204` 的法學知識與英文 `Q`、`S`、`M`。
  - 考試整份答案總表 `A`（**不掛到任何單科目**）。
- PDF 僅允許官方 `https://wwwq.moex.gov.tw/exam/wHandExamQandA_File.ashx` 的核准參數；限制每個檔案 8 MiB、限制最大頁數，透過 `pypdf` 嘗試解析，記錄 `SHA-256`、位元組數、頁數與文字標題是否吻合。
- 申論／單選題目尚未逐題抽取；**PDF 可讀、標題看似符合不等於答案正確**。沒有法條及判決核對，也不會生成詳解或國考分數。
- 索引中的 `answer_verification`、`quiz.js`、原有申論與選擇題歷史資料**都不修改**。
- 來源失敗、PDF 格式錯誤、官網改變參數格式時，該檢查失敗，舊來源不被覆寫。
- 下載/解析報告僅上傳到 GitHub Actions 的短期 artifact，不進入公開主分支資料庫。
- 報告固定包含：`publication_allowed: false`、`scoring_enabled: false`、`answer_choices_verified: false`，保留「未核驗」標記。

## 驗收標準

- [x] 本機／測試夾具能攔截非官方來源、錯誤考試代碼、跨試卷答案配對及偽造 PDF。
- [x] 能明確區分 `Q`／`S`／`M`／`A`，更正連結必須符合試卷完整識別鍵。
- [x] 假定 PDF 可正常讀取時，品質報告仍不得發布正式計分。
- [ ] GitHub Runner 7 份官方 PDF 真實連線、PDF 解析與 SHA-256 成功，附 artifact。
- [ ] 試卷與類科上下文逐筆核對，消除可疑分類警報。
- [ ] 針對正式答案、修正答案、特殊給分逐題建立可追溯對照。
- [ ] 逐選項詳解的法條及實務來源驗證。
- [ ] 經過上述阻斷項目驗收與使用者核准，才考慮合併。

### 切勿混淆「PDF 連結驗證」與「題庫發布」

目前僅有來源 PDF 可讀性和少量樣本的元資料核對。即使 GitHub Actions 全綠，也只代表已執行的範圍通過測試；**不能聲稱 80 份試卷、其所有題號、最新答案或法律詳解已被核驗**。
