# LexFlow V0.3｜跨科目批次題庫處理引擎（候審版本）

## 定位與保護規則

此模組不是逐題已核驗的正式題庫，也不代表已完成 AI 法律詳解。

- 目的：讓同一個處理器讀取任一年度的 **考選部候審索引 JSON**，免去為每份試卷、每個科目手動寫解析器。
- 輸入：`lexflow.moex.index.v1`，可由官方 CSV 候審索引或個別考試頁備援索引產生。
- 輸出：**獨立** `lexflow.moex.universal.batch.v1` JSON 候審報告；原始索引、`app.js`、`quiz.js`、瀏覽器本機紀錄完全不改。
- PDF 以 `Q` 試題、`S` 公布標準答案、`M` 更正答案分開保存。全考試答案總表 `A` 只屬於考試層級，**不會錯配為個別科目答案**。
- 有 `c/code/q/s` 身分欄位的官方 Q/S/M 文件，必須逐一符合相同考試、類科、科目及節次。其他 CSV 官方 PDF 網址只可確認來源，**不得自動推定答案配對**。
- 僅 HTTPS 考選部網域；阻擋外部主機、帳密網址、非標準埠、惡意參數及非預期跳轉。來源無法取得時，保留原有紀錄。
- **沒有「可計分」的自動升級捷徑**：完整題文、選項、原答案、最終更正、特殊給分及法源都需要後續來源核對。

## 批次工作方式

1. 收取官方索引，正規化試卷身分，選取最多 `--max-papers` 筆具有代表性的試卷。先覆蓋民法、刑法、憲法，再視額度增加混合科目。
2. 預設僅產生離線「規劃」資料，**不連線下載 PDF**。必須明確輸入 `--download-documents` 才會下載 PDF。
3. 下載時僅檢查可讀性、頁數、SHA-256、預期科目文字；對讀取得到的題號只產生原始文字 **候審預覽**。不能因 PDF 結構正常就宣稱題文、選項或答案正確。
4. 同時保留公布答案與更正答案，發現 `M` 時新增人工審查警示；不直接用 `M` 覆蓋 `S`，不推定特殊給分。
5. 單份 PDF 失敗，只隔離該份試卷；其他成功試卷仍保留在同一報告。當全部失敗或加上 `--require-all` 的嚴格驗收發生異常時停止，舊報告不變。
6. 每批最多 12 份試卷及 24 次 PDF 嘗試（可再調低），避免對考選部造成過量流量。

## 操作範例（僅限開發分支）

最安全的本機模式，對下載後的候審索引產生規劃：

```bash
python scripts/moex_batch_engine.py \
  --input-index downloaded-official-candidate.json \
  --max-papers 4 --max-documents 9 \
  --output /tmp/lexflow-universal-plan.json
```

GitHub CI 的 **小樣本真實來源**測試（只對經核准的 114120 考試頁）：

```bash
python scripts/moex_batch_engine.py \
  --live-exam 114120 \
  --max-papers 3 --max-documents 9 \
  --download-documents --require-all \
  --output /tmp/lexflow-universal-review.json
```

使用已取得的 CSV 索引，即可處理不同年度的候審文件 URL，無需在引擎寫死年度或 2201 民法。至於 **主動發現其他年度的 HTML 考試頁面**，需要先擴充上游來源網址白名單，不應取消官方來源驗證。

## 已驗證範圍與目前缺口

- 離線案例：不同民國年度、三核心領域、混合科目、Q/S/M 配對、更正隔離、惡意網址、跳轉、重複試卷、文件預算、個別失敗與不可計分旗標。
- 曾由 GitHub 取得的 **114120 官方 80 筆候審索引**，可在本機規劃模式選出跨民法、刑法、憲法與混合科目的候審樣本；不表示這 80 份 PDF 全部已下載、核對或能計分。
- 新增獨立 `universal-batch-smoke` GitHub job，**只有成功執行後**才能宣稱跨科目的真實 PDF 批次測試通過。
- **尚未完成**：多年度全量自動發現、不同掃描 PDF 的 OCR、可靠拆出每一道題目及四個選項、最終答案更正整合、法條與法律詳解驗證，以及接入正式可計分學習介面。這些不能由通用索引功能推論完成。
