# LexFlow V0.4｜官方全量目錄與統一試卷身分（第一、二階段）

## 這次真正改變什麼

以 `scripts/moex_catalog_bridge.py` 作為**完整考試目錄的優先讀取入口**。它現在直接接收考選部原始 14 欄 CSV、既有的增強 CSV、或既有 `official_catalog.sqlite`，而不再要求先把原始 CSV 人工標成「法律候選」才能使用預設篩選。這只修改**目錄發現和整卷身份分類**，**不改變 V0.3 的正式發布候審機制、作答儲存或 PDF 引擎**。

仍保留 `scripts/moex_index.py` 的原有三領域索引，作為 V0.3 的舊版相容入口；它不再代表全量國考收錄範圍。不要單獨擴大 `FOCUS` 就把歷屆的複合科目錯誤歸入刑法、民法、憲法。GitHub Actions 的定期正式候審更新亦**尚未切換至全量目錄**：這屬於後續批次、排程與發布階段，不可偷宣稱已自動化。

## 核心設計

- 來源必須是考選部官方 14 欄格式，保留官方的**考試名稱、年度、等別、類科組別、科目全名、試題型態、Q／S／M 網址及更正註記**。
- 科目「綜合法政知識與英文」是一個官方完整名稱，不會拆成「憲法」與「英文」兩卷；其他「綜合法學（一）／（二）」同理。附加的 `title_domain_tags` 只代表標題**明示**的搜尋提示（避免把「國民法官法」誤標為民法、「監獄行刑法」誤標為刑法），不能冒充卷內逐題爭點或更改官方科目。
- 法律候選為**保守的名稱篩選**（明確法律、綜合／基礎、跨領域待複核）；其餘資料仍保留於原始目錄，必要時 `--scope all` 可取用。它不宣稱已全文分析所有非候選卷。
- 題型由官方「測驗題／申論題／混合題／實地考試」決定，混合卷仍是一份完整試卷；Q／S／M 仍依相同考試、類科、科目參數嚴格配對。
- **相同的官方 Q 文件身分**可有多個來源列與類科關聯，必須保留每個 `source_appearances`；**不同的 Q 文件身分**不能只憑相同科目名稱併成一份。若兩個不同網址的 PDF 實際完全相同，只有下載後核對 PDF SHA-256 才能建立內容等價關係。
- 來源中的科目、題型、答案 URL 或分類標記自相矛盾時進入隔離；不可偷偷選一個作為正確來源。
- 這些統計及選卷工作全部**離線、未下載 PDF、不修改既有索引、不正式發布、不計分、不觸碰私人作答**。

## 執行方式（不連網）

```sh
# 完整清點：不下載、不寫入原始 CSV
python scripts/moex_catalog_bridge.py inventory \
  --catalog path/to/ExamQandA_Csv.csv \
  --output /tmp/lexflow-v04-inventory.json

# 可直接從原始官方 CSV 篩選（不需要預處理成 SQLite）
python scripts/moex_catalog_bridge.py plan \
  --catalog path/to/ExamQandA_Csv.csv \
  --scope candidates --years 113,114 --limit 9 \
  --output /tmp/lexflow-v04-9-papers.json

# 精確比對年度、考試代碼、類科組別、科目名稱、官方題型
python scripts/moex_catalog_bridge.py plan \
  --catalog path/to/ExamQandA_Csv.csv \
  --scope candidates --years 114 --exam-code 114120 \
  --class-group '法院書記官類科' --subject '民法概要' \
  --types 混合題 --limit 3 --output /tmp/civil-list.json
```

`--exam-code`、`--class-group`、`--subject` 可重複指定。**類科、科目均精確比對官方原文**，不默默改字或用 AI 猜測。全部命令若目標輸出已存在會安全拒絕覆寫。

## 本次完成標準與後續工作

1. 原始官方 CSV、整理後 CSV 與 SQLite 的全量分類、數量、官方身分一致。
2. 同 Q 來源關聯可去重但保留全部類科；不同來源不得因科目相同而誤合併。
3. 來源矛盾、錯誤主機、Q／S／M 不同卷、擅改法律候選分類均安全隔離。
4. 測驗、申論、混合試卷可以共同進入同一 `make_plan`，維持 `scoring_enabled:false`、`publication_allowed:false`。
5. 下載、OCR、申論擬答、正式題庫發布、跨年度自動排程留給下一階段；**本階段不能聲稱完成**。

現有 `main`、Draft PR 的人工核對門檻以及舊版 V0.2／V0.3 作答紀錄都維持原樣。本階段若推送，也只能推送到既有 Draft PR 開發分支。
